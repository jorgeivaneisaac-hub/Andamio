🏗️ Andamio

Andamio acompaña a la persona desde su primer «hola mundo» hasta proyectos maduros, en español y sin obligarla a aprender un motor de plantillas.

Generador interactivo de proyectos: llama a los creadores oficiales de cada lenguaje y añade encima estructura, CI, pre-commit, gobernanza y contexto para agentes de IA.

Regla del proyecto: algo no está terminado hasta que se generó y se probó de punta a punta (compilado o ejecutado). Escrito no es lo mismo que probado. Estimación propia: 3 días de lógica, 1–2 días de JSON y varios días de pruebas.

Hecho y verificado

  • Bug del writer original (creaba un archivo Length) corregido en write_file; UTF-8 sin BOM y no pisa archivos.
  • Writer en .NET puro, sin cmdlets del sistema; solo git es externo.
  • Dividido en writer-dirs, writer-files y create-project-core, probado junto (Python y C++, git en main). copy_files reconstruido.
  • main.c de los 3 niveles compila con -Wall -Wextra; CMakeLists.txt compartido C/C++ compila con cmake.
  • environment-installer: detección de SO y gestor verificada en Linux/apt (el Read-Host no se pudo probar).
  • tools-catalog.json válido y revisado; historial de git sin secretos; estructura modular de config.
  • Medido: copiar 200 archivos pequeños tarda ~46 ms en secuencial y ~1550 ms con -Parallel; pwsh arranca en ~230 ms.

Hitos

v0.1Motor + Aprendizaje

Python, C, JS, HTML de punta a punta.

  • InfoLenguaje + reader-json (yaml/toml después); reader-general elige por extensión.
  • index.json → X-config.json → templates/ con plantilla y valores.
  • Marcadores {{…}} y aviso si queda uno sin reemplazar.
  • Copiador salta .gitkeep/.null. .null = no aplica, .gitkeep = pendiente.
  • Core solo orquesta; git opcional con confirmación.
  • X-config: version, extensiones, carpetas, niveles 1–3; comando_init ≠ comando_prueba.
  • Python y C en 3 niveles, JS y HTML nivel 1, APRENDE.md.
  • Pester genérico que omite si falta la herramienta; requiere PowerShell 7+.
  • Copiador y carpetas en secuencial.

v0.2Cuestionario y plan

  • Preguntas como datos JSON: de ahí salen la TUI, los flags y el archivo de respuestas.
  • Mostrar el comando equivalente (solo texto; probar bash y PowerShell).
  • Plan con riesgo bajo/medio/alto: [s] todo, [b] solo bajo, [n] cancelar.
  • --plan simulación y modo sin preguntas; flags en español con alias.
  • Sobrescritura (propuesta): respeta contenido, rellena vacíos, lote s/n/todos/ninguno, .example, resumen.
  • project.json con respuestas y versión, sin datos sensibles.
  • Logger, validación, defaults, ayuda, aviso de correo visible, próximos pasos.

v0.3Instalador y doctor

  • tools-catalog.json con apt, pacman y winget; comando exacto y confirmación.
  • sudo -v; nunca se guardan contraseñas.
  • Sin gestor: cancelar y mostrar pasos manuales con enlace oficial.
  • No descarga instaladores de la web; avisar de reiniciar la terminal.
  • andamio doctor (nombre por decidir: doctor, revisar, chequeo, salud).
  • comando_init oficial opcional y registro de su versión.
  • Casos raros: vscode (repo de Microsoft en apt), cargo (versión vieja), gnucobol (AUR), gfortran (MSYS2), vercel (fuera), C# = SDK de dotnet.

v0.4Config de usuario y externa

  • Carpeta al primer uso: %APPDATA%\andamio, ~/.config/andamio, ~/Library/Application Support/andamio.
  • preferencias.json, perfiles/, plantillas/, registro/. Prioridad: proyecto > usuario > interna.
  • -Config archivo con "extiende"; andamio config; errores con línea exacta.
  • Una config externa define estructura, no comandos, salvo autorización.
  • Retrocompatibilidad: version en todo, reglas en JSON, "rules": null real (no el texto), [a]ctualizar con .bak / [t]raducir / [v]er, últimas 3 versiones, ejemplos en tests/.
  • Perfiles guardados: andamio nuevo --perfil mi-api.

v0.5Nivel Medio y plataformas

  • Nivel 2: Python, C, C++, JS y web básica; pre-commit, CI simple, changelog.
  • Selector GitHub / GitLab / ambos / ninguna.
  • GitHub: workflow por lenguaje, plantillas, dependabot. GitLab: .gitlab-ci.yml orquestador, issue_templates + merge_request_templates, Renovate.
  • gh/glab: repo remoto privado por defecto y con confirmación.
  • Pendiente: Java sin soporte en pre-commit/CI/VS Code, Ruby sin ganchos, pre-commit desactualizado, tasks.json fijo, node-ci con npm ci.
  • web-static y web-sql con contenido válido (sin package.json vacío).

v0.6+Avanzado y proyectos grandes

  • Nivel 3: Rust, Go, Python (+ TS, Java, Ruby, PowerShell, web con servidor y SQL, multi-lenguaje).
  • Modo agregar a proyecto existente; subir de nivel sin pisar.
  • Estructura apps/ services/ libs/; CI solo de lo que cambió; org y licencia parametrizables.
  • Perfiles: distro, multilanguage, web-static, web-sql.
  • Generadores externos (Copier, Yeoman, cargo generate, dotnet new): se lanzan, no se renderizan. Riesgo alto, comando desde tabla interna, nunca --trust automático; el catálogo indica qué requiere cada uno.
  • Framework de plantillas: andamio plantilla nueva y validar (esquema JSON + comando_prueba).
  • Docker, Kubernetes, catálogos npm/pip y actualizar proyectos ya generados (modelo Copier).

Antes de dar un lenguaje por terminado: investigar comando_init e instalador, generarlo de verdad y correr su comando_prueba. Cada uno trae al menos una sorpresa.

Decisiones de diseño

  • Datos en JSON, lógica en .ps1.
  • Plantillas = archivos reales con {{MARCADOR}}; sin Jinja, para que compilen tal cual.
  • Los comandos salen de una tabla interna, nunca de un archivo de respuestas ni de una config externa.
  • Nunca se guarda una contraseña.
  • No se pisan archivos con contenido.
  • Un solo modelo interno, InfoLenguaje.
  • Agregar un lenguaje o formato es sumar, no modificar.
  • Los niveles son sugerencias, no muros.
  • Solo apt, pacman y winget en v0.x.
  • comando_init ≠ comando_prueba.
  • Nombres técnicos en inglés; contenido y mensajes en español.
  • Sin probar no está terminado.

Docker para usuarios finalesAndamio escribe en el disco del usuario; solo sirve como entorno de desarrollo.

Cientos de lenguajes escritos por una personaLa arquitectura permite aportes de ~10 min, pero cada lenguaje exige investigar y probar.

Limpieza pendiente

Estructura y código

  • especifcs → especificos.
  • .gitlab/template → issue_templates y merge_request_templates.
  • Data/ contiene también lógica; nombre engañoso (opcional).
  • Carpetas vacías no viajan en git: usar .null o .gitkeep.
  • create_struct aún lee el config.json viejo.
  • Rutas de LICENSE_* y CODE_OF_CONDUCT apuntan a la estructura vieja.
  • core/main.ps1 con código de demostración y valores fijos.
  • init_git debe comprobar que git exista.

Plantilla de C y repo

  • Typos: «yo» duplicado y «configuraaciones».
  • El comentario dice gcc pero el catálogo instala clang.
  • Confirmar que src/main.c coincida con la ruta de c-config.json.
  • Archivos duplicados raíz vs include/ con tamaños distintos: decidir cuál se distribuye.
  • Archivos vacíos históricos: AGENTS.md, CHANGELOG.md, GEMINI.md, CHAT_GPT.md.
  • CLAUDE.md genérico de ~55 KB: sustituir por contexto generado.
  • El README promete más de lo que el código hace hoy.

Tesis y evidencia

  • Una afirmación central; lo demás la sostiene: niveles de aprendizaje, plantillas sin motor y español. Extensiones: interoperabilidad, framework de plantillas y contexto para agentes.
  • Evidencia: medir cuánto tarda alguien en tener su primer programa corriendo, con y sin Andamio, con 5–10 personas reales y sin ayudarles.
  • No vender rendimiento: se midió y el paralelo era ~30× más lento en archivos pequeños.
  • Repo privado hasta pulirlo; antes de publicar, revisar el correo de los commits (noreply) y opcionalmente gitleaks.
  • Meta de distribución: README honesto, GIF de la TUI, CONTRIBUTING con «cómo agregar un lenguaje», versionado 0.x con changelog y tags.
